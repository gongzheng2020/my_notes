#### 一、核心概念（1句话定义）

FreeRTOS 是一个用 C 语言编写的**开源轻量级抢占式实时操作系统**，专为嵌入式微控制器设计，内核提供**任务调度、任务间通信、中断管理和内存管理**，并具备**高度的跨架构可移植性**。

---

#### 二、任务与任务状态（必背）

**1. 状态转换图（4种状态）**

![[Pasted image 20260708151844.png]]

> **运行 (Running)** → **就绪 (Ready)** → **阻塞 (Blocked)** → **挂起 (Suspended)**

- **运行**：当前占用 CPU。
    
- **就绪**：准备就绪，等调度器分配 CPU。
    
- **阻塞**：等待事件（如 `vTaskDelay`、队列/信号量超时）。**这是大多数任务的状态。**
    
- **挂起**：由 `vTaskSuspend` 主动暂停，不能被调度，需调用 `vTaskResume` 才能恢复。
    

**2. 任务优先级（Priority）**

- 数值越大优先级越高（0 为最低）。
    
- **抢占式调度**：高优先级任务**一旦就绪**，立即抢占低优先级任务。
    
- **时间片轮转（Time Slicing）**：同优先级任务按照时间片轮流执行（时间片常为 1 个 Tick）。
> FreeRTOS 还包含一个协作式调度，所有任务依次执行，无优先级概念。

**3. 空闲任务（Idle Task）**

- 最低优先级（0），系统自动创建。
    
- **作用**：当所有其他任务阻塞时运行，防止 CPU 空转（通常执行 `WFI` 指令省电），并负责**清理被删除任务的内存**。

#### 三、任务间通信与同步（高频考点）

| 机制                           | 核心作用       | 特性 / 注意点                                                                     |
| ---------------------------- | ---------- | ---------------------------------------------------------------------------- |
| **队列 (Queue)**               | 消息传递（数据拷贝） | FIFO 方式，**发送/接收均有超时机制**；**支持多个任务同时阻塞等待同一个队列**。                               |
| **信号量 (Semaphore)**          | 同步 / 资源计数  | **二值信号量**（类似互斥锁，常用于中断给任务发信号）；**计数信号量**（管理资源池如串口、内存池）                         |
| **互斥量 (Mutex)**              | 保护共享资源     | 拥有**优先级继承**特性（防止优先级翻转）；**由获得锁的任务去释放，谁拿谁放**；**递归信号量**一种特殊形式，允许同一个任务多次获取同一个资源。 |
| **事件组 (Event Group)**        | 多事件同步      | 一个任务等待多个事件发生（如 A 和 B 都完成）；支持多个任务同步。                                          |
| **任务通知 (Task Notification)** | 轻量级通信      | 速度**最快**，无需创建队列/信号量（直接向目标任务发送 32 位数据/状态）。**效率最高，但只能一对一。**                    |

#### 四、内存管理（知识拓展）

- **Heap 分配策略**（在 `FreeRTOSConfig.h` 中配置）：
    - **Heap_1**：只能申请，**不能释放**（适合永不删除任务的项目）。
    - **Heap_2**：支持释放，但**不合并**碎片（易产生内存碎片）。
	- **Heap_3**：**直接使用标准库 malloc/free**，但开销较大。
    - **Heap_4**：**最常用**，支持释放和**内存块合并**，有效防止碎片。
    - **Heap_5**：多块不连续内存区域合并管理，如需要同时使用内部RAM和外部RAM（适用于内存分片架构）。

#### 五、中断管理与临界区（面试防坑）

1. **中断处理原则**：**ISR（中断服务程序）要短、快、轻量**。不要在 ISR 中做复杂计算。
    
2. **延迟中断处理（Deferred Interrupt）**：ISR 中只做“标记”动作（如发送信号量、写入队列），把复杂逻辑放到**高优先级任务**中去处理。
    
3. **中断安全 API**：在 ISR 中调用 FreeRTOS 的 API，**必须使用带 `FromISR` 后缀的函数**（例如 `xQueueSendFromISR`、`xSemaphoreGiveFromISR`）。
    
4. **临界区（Critical Section）**：
    - 使用 `taskENTER_CRITICAL()` 和 `taskEXIT_CRITICAL()` 包裹需要原子性操作的代码（如修改全局变量）。
    - **效果**：关闭中断，强制独占 CPU，防止任务切换；**注意**：临界区必须极短，否则严重影响系统实时性。

#### 六、高频面试题与防坑指南（必看）

- **Q1：什么是优先级翻转？如何解决？**
    - **现象**：高优先级任务 H 被低优先级任务 L（占用着锁）阻塞，而 L 又被中优先级任务 M 抢占，导致 H 无限期等待。
    - **解决**：FreeRTOS 对**互斥量（Mutex）**实现了**优先级继承**。当 H 被 L 阻塞时，系统会把 L 的优先级临时提升到 H 的级别，H 获得锁后再降回原级别。
        
- **Q2：任务堆栈溢出如何检测？**
    - 方法1：利用空闲任务检查（`configCHECK_FOR_STACK_OVERFLOW`）。
    - 方法2：使用 `uxTaskGetStackHighWaterMark()` 获取任务历史最小剩余栈空间。
        
- **Q3：`vTaskDelay` 和 `vTaskDelayUntil` 有什么区别？**
    - `vTaskDelay`：**相对延时**。指“从现在起，阻塞 N 个 Tick”。
    - `vTaskDelayUntil`：**绝对延时**。指“阻塞到指定的 Tick 数时刻”，**精确控制任务执行的固定周期**（适合 ADC 采样、LED 闪烁等需要固定频率的任务）。
        
- **Q4：为什么在 ISR 中不能使用普通的 API？**
    - 因为普通 API 内部会试图切换任务（如解开队列阻塞），而 ISR 运行在中断上下文中，没有任务上下文；强行调用会导致系统崩溃。必须使用 `FromISR` 后缀的 API。

#### 七、一页纸记忆口诀

> **抢占调度看优先，同层时间片轮转。**  
> **就绪运行阻塞挂，空闲任务清内存。**  
> **队列传递副本去，二值计数信号量。**  
> **互斥继承防翻转，任务通知最快传。**  
> **中断处理要短平，FromISR 后缀记心间。**  
> **临界区关中断，绝对延时要算准。**

#### 一些不会的面试问题

Q：请解释一下在FreeRTOS中队列的作用和用途。
A：队列允许任务之间通过发送和接收消息来通信，是一种先进先出（FIFO）的数据结构，任务可以向队列发送数据，其他任务则可以从队列中取出数据。队列对于任务解耦和同步非常有用，因为它们允许任务以异步的方式交换信息。

Q：请解释一下FreeRTOS中的软件定时器以及它们的工作原理。
A：软件定时器是FreeRTOS提供的一种机制，允许任务在将来的某个时间点被唤醒。软件定时器是使用FreeRTOS的调度器和时钟滴答来模拟的。当定时器到期时，与其关联的任务将被添加到就绪列表中，以便在下一个调度点执行。可以通过ID在同一个回调中执行多个任务。

Q：什么是优先级翻转？如何解决？
A：高优先级任务被低优先级阻塞（低优先级先取得锁），而低优先级又被中优先级抢占（假设中优先级不需要锁），导致高优先级必须等待中优先级执行完毕，形成“优先级倒置”的现象。使用互斥锁，其带有优先级继承机制，能够临时提高优先级，让低优先级尽快完成；或直接将拿到锁的任务升至一个最高优先级。

Q：什么是临界区？如何保护临界区？
A：临界区其实就是一段在执行的时候不能被中断的代码段。进入临界区后，系统会通过关中断或挂起调度器来确保代码段的原子性。

Q：你能解释一下FreeRTOS的tickless模式吗？
A：tickless模式**是FreeRTOS中的一种节能机制**，**如果系统处于空闲状态（所有任务都处于阻塞状态，或者没有任何时间敏感的操作需要执行），时钟滴答可以停止**，从而减少CPU的功耗。

Q：请描述一下FreeRTOS中事件组的工作原理及其用途。
A：事件组是FreeRTOS中的一种同步机制，它允许任务之间通过**一组事件的设置和清除来通信和同步**。事件组**是一个32位的二进制字段**，每个位可以代表一个事件。任务可以使用**xEventGroupCreate()创建事件组**，并**使用xEventGroupSetBits()和xEventGroupClearBits()来设置和清除事件**。其他任务可以通过**xEventGroupWaitBits来等待特定的事件位状态变化**。

Q：请解释一下FreeRTOS中的时间管理机制。
A：FreeRTOS中的时间管理主要依赖于时钟滴答和软件定时器。时钟滴答是定期发生的事件，用于任务调度和时间函数的执行。软件定时器则用于实现定时任务，当定时器到期，回调函数将执行。

Q：在FreeRTOS中，静态内存分配和动态内存分配有何不同？为什么不推荐频繁使用动态内存？
A：静态内存分配是在编译时确定的，通常用于创建固定大小的内存块，如任务栈和队列。动态内存分配则是在运行时进行的，允许根据需要分配和释放内存。
频繁动态分配**会产生内存碎片**，导致系统长期运行后因申请不到连续大块内存而崩溃，同时其**执行时间不确定及内部关调度器**的操作，也会直接破坏 FreeRTOS 的硬实时性。

Q：任务通知是怎么实现的？
A：**直接修改目标任务控制块**（TCB） 内部的 32 位通知值和状态标志位，无需经过队列或信号量等中间结构，速度最快，但仅限一对一通信。

Q：RTOS的实时性是如何实现的？
A：RTOS（如 FreeRTOS）的实时性，核心在于实现 **“确定性”** 和 **“极快响应”**。它的实现主要由以下四点支撑：
1. **中断抢占（最高优先级响应）**：硬件中断是系统响应的“第一触角”，直接打断任务执行，确保外部事件被立刻感知。
2. **抢占式调度算法**：如果高优先级任务就绪，它会**立即抢占**当前运行的低优先级任务，保证紧要任务永远优先获得 CPU。
3. **可预测的执行时间**：RTOS 内核要求所有系统调用（如任务切换、信号量释放）的执行时间是固定的，且**最大化缩短临界区长度**，确保任务切换和中断响应时的延迟可控。
4. **精确的滴答（Tick）驱动**：利用高频的系统滴答定时器提供精确的时间基准，支撑 `vTaskDelay` 和延时超时机制，做到微秒/毫秒级的时间控制。

Q：中断专用函数与普通函数区别？
A：中断专用函数通常带FromISR后缀，不允许阻塞，同时。

Q：哪些机制会触发任务切换？任务切换流程？
A：高优先级任务就绪会切换、同级任务时间片轮转会切换、或者是触发中断切换。首先是触发PendSV中断，接着保存旧任务当前现场，主要是一些寄存器入栈，并将栈指针保存在TCB中，接着恢复新任务现场，从新任务TCB中取出栈指针，并将寄存器出栈，新任务开始运行。中断与任务切换还有些不同，中断是由硬件触发的，使用的是主堆栈（MSP），而任务切换是由软件触发的，用PendSV处理，用的是任务堆栈（PSP），且中断中必须使用中断专用函数。

Q：二值信号量与互斥锁的区别？
A：二值信号量用于任务间同步，互斥锁用于共享资源保护，主要区别就是互斥锁是有优先级继承和所有权机制的。

Q：任务大小分配原则？
A：一般是根据任务复杂程度和变量所占空间大小，先给一个较大的初始值，再直接运行该任务并通过uxTaskGetStackHighWaterMark()函数去实时获取当前任务实际最大栈大小，再留20%到30%的余量，从而确定最终栈大小。

Q：优先级分配原则？
A：一般是根据任务所需的**实时性、周期和中断响应情况进行划分**，比如说类似于急停保护、控制算法之类的任务设置为高优先级（一般优先级范围为0~31），通信之类的任务设置为中优先级，按键、显示之类的任务设置为低优先级。

Q：FreeRTOS 和 Linux 二者调度算法有何差异？
A：FreeRTOS 采用固定优先级的抢占式调度，追求确定性和硬实时响应；Linux 默认采用 **CFS（完全公平调度器）**，追求多任务公平性和吞吐量。

Q：pendSV、SVC、sysTick？
A：pendSV负责任务上下文切换；SVC负责启动第一个任务；sysTick是一个周期性硬件定时器，用来给整个系统提供时钟基准。

Q：FreeRTOS移植过程？
A：去官网下载FreeRTOS的源代码，进入source文件夹，将其中的C文件和include中的头文件复制到工程中，再进入port文件夹，将对应架构的port.c文件和heap_4.c文件复制到工程中，最后再从官方demo中挑选符合自己单片机架构中的例子，将其中的FreeRTOSConfig.h配置文件复制到工程中；随后在配置文件尾部中添加PendSV、SVC、SysTick中断函数的宏定义，并在it.c文件中注释PendSV和SVC函数，并将原本的SysTick_Handler函数，实现过程主要就是用已有的xPortSysTickHandler函数进行替换；然后还能在配置文件中对内核其他参数进行配置，包括堆大小、最大任务数、节拍频率等等，还能添加和裁剪部分功能。
