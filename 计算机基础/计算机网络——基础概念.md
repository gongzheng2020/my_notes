### TCP和UDP的区别

#### 一、核心定义

- **TCP**：面向连接、可靠传输、保证顺序。
    >TCP 的“保证顺序”是利用序列号，在接收端将乱序的数据包重新排列成正确的顺序。
    >UDP 则不进行这个排列，将可能乱序的数据直接交给应用程序。
- **UDP**：无连接、不可靠传输、注重速度。

>UDP就像寄信，你只要知道地址，写好信扔进邮筒就行，不需要先和收件人约好时间。
>TCP就像打电话，必须先接通。

#### 二、核心对比表（必背）

|对比维度|**TCP**|**UDP**|
|---|---|---|
|**连接方式**|面向连接（三次握手）|无连接|
|**可靠性**|**可靠**（确认、重传、校验）|**不可靠**（可能丢包、乱序）|
|**传输顺序**|按序到达|不保证顺序|
|**传输速度**|较慢（开销大）|**极快**（无额外控制）|
|**头部开销**|20字节|8字节|
|**流量控制**|支持（滑动窗口）|不支持|
|**拥塞控制**|支持（慢启动、拥塞避免）|不支持|
|**应用场景**|网页、邮件、文件传输|视频流、游戏、DNS查询|

#### 三、关键机制速记

- **TCP 可靠性**：确认应答（ACK）、超时重传、校验和、序列号（保证顺序）。
    
- **TCP 连接管理**：**三次握手**（建立连接）→ **四次挥手**（释放连接）。
    
- **UDP 优势**：无连接、无重传、无拥塞控制，延迟极低。
    

#### 四、面试追问速答

- **Q: 为什么 UDP 适合实时应用？**  
    **A:** 因为 UDP 没有连接建立、确认重传等开销，延迟极低，能容忍少量丢包（如视频通话中短暂花屏可接受，但延迟不可接受）。
    
- **Q: TCP 如何保证可靠传输？**  
    **A:** 通过**序列号**（保证顺序）、**确认应答**（ACK）、**超时重传**、**校验和**（数据完整性）和**流量/拥塞控制**。
    
- **Q: 什么时候应该用 UDP 而不是 TCP？**  
    **A:** 当**实时性**比**可靠性**更重要时，如直播、在线游戏、DNS查询。这些场景中，延迟比丢包更影响体验。
    

#### 五、记忆口诀

> **TCP 可靠保顺序，三次握手四次挥。**  
> **UDP 极速无连接，视频游戏 DNS。**  
> **速度慢的比不过，实时场景选 UDP。**

### HTTP请求方式

#### 一、核心清单（HTTP/1.1 原生 8 种）

> **GET、POST、PUT、DELETE、HEAD、OPTIONS、TRACE、CONNECT**

|方法|核心作用|是否安全|是否幂等|典型场景|
|---|---|---|---|---|
|**GET**|获取资源|✅ 安全|✅ 幂等|查询数据、加载页面|
|**POST**|提交数据（可能修改状态）|❌ 不安全|❌ 不幂等|表单提交、创建订单|
|**PUT**|全量更新资源|❌ 不安全|✅ 幂等|用户信息全量更新|
|**DELETE**|删除资源|❌ 不安全|✅ 幂等|删除文章/用户|
|**HEAD**|仅获取响应头（无Body）|✅ 安全|✅ 幂等|检查资源是否存在/是否更新|
|**OPTIONS**|查询支持的/跨域预检|✅ 安全|✅ 幂等|CORS 预检请求|
|**TRACE**|回显请求（调试用）|✅ 安全|✅ 幂等|**通常禁用（安全风险）**|
|**CONNECT**|建立代理隧道（如 HTTPS）|❌ 不安全|❌ 不幂等|底层代理处理，业务层极少用|

>**安全**特指这个请求方法不会改变服务器上的资源状态，也就是“只读”操作
>**幂等**是对同一个资源，执行一次请求和执行多次请求，产生的副作用（也就是对服务器状态的改变）是相同的。

#### 二、扩展方法（非原生）

- **PATCH**（RFC 5789，2010）：**局部更新**资源（只改部分字段）。
    
    - 非幂等（多次局部修改可能导致不同结果）。
        
    - vs PUT：PUT 是**全量替换**，PATCH 是**增量修改**。
        

#### 三、核心概念辨析（高频考点）

- **安全（Safe）**：方法**不修改**服务器资源状态。**只有 GET、HEAD、OPTIONS、TRACE 是安全的。**
    
- **幂等（Idempotent）**：对同一资源发起**一次或多次**请求，产生的**效果相同**。**POST 和 PATCH 不幂等，其余均幂等。**
    

#### 四、面试追问速答

- **Q: 为什么 HttpServlet 源码中只定义了 7 种方法（少了 CONNECT）？**  
    **A:** 原始规范（RFC 2616）有 8 种。但 **TRACE** 因安全风险（XST 攻击）通常被禁用，**CONNECT** 由底层服务器（如 Tomcat）处理，无需业务代码干预。因此 Servlet 仅暴露了 GET、POST、PUT、DELETE、HEAD、OPTIONS 和 TRACE（共 7 种）。
    
- **Q: PUT 和 POST 的区别？**  
    **A:** PUT 是**全量更新**，且**幂等**；POST 是**提交数据**（通常是新增或触发操作），**不幂等**。
    
- **Q: 各 HTTP 版本支持哪些方法？（HTTP/1.0、1.1、2、3）**  
    **A:** HTTP/1.0 支持 GET、POST、HEAD；HTTP/1.1 增加 PUT、DELETE、OPTIONS、TRACE、CONNECT；HTTP/2 和 HTTP/3 **未新增方法**，兼容旧版。

#### 五、记忆口诀

> **GET 查，POST 改，PUT 全量换，DELETE 删。**  
> **HEAD 查头，OPTIONS 探路，TRACE 回显风险大，CONNECT 隧道代理管。**  
> **安全只读 GET/HEAD，幂等除 POST/PATCH 全过关。**

### GET请求和POST请求

#### 一、核心定义

- **GET**：**获取资源**（读取数据）。参数在URL中，**安全、幂等、可缓存**。
    
- **POST**：**提交数据**（改变状态）。数据在请求体中，**不安全、不幂等、不缓存**。
    

#### 二、核心对比表（必背）

|对比维度|**GET**|**POST**|
|---|---|---|
|**核心用途**|获取资源（查询）|提交数据（新增/操作）|
|**数据传输位置**|参数附加在 **URL** 中|数据放在 **请求体 (Body)** 中|
|**数据大小限制**|受URL长度限制（约2KB-8KB）|**理论上无限制**（取决于服务器配置）|
|**安全性（隐私）**|参数**可见**于地址栏，不适合敏感信息|参数**不可见**于地址栏，相对隐蔽|
|**安全性（状态）**|**安全**（不修改服务器状态）|**不安全**（可能修改服务器状态）|
|**幂等性**|✅ **幂等**|❌ **非幂等**|
|**缓存**|✅ **可被缓存**（浏览器/代理）|❌ **通常不被缓存**|
|**编码类型**|只允许 ASCII 字符|支持多种编码（如 JSON、XML、二进制）|

#### 三、深入理解“安全性”的细微差别（面试常考）

面试官通常会把“安全性”拆成两个维度来问，注意区分：

1. **数据隐私维度**：
    
    - GET 的参数直接暴露在 URL 中，容易被浏览器历史记录、代理服务器记录，因此**不适合传输密码等敏感信息**。
        
    - POST 的数据在 Body 中，不会直接暴露在 URL，**相对更隐蔽**。
        
    - **重要提醒**：**无论是 GET 还是 POST，如果不使用 HTTPS，数据都是明文传输，都不安全。** HTTPS 是保护数据隐私的底线。
        
2. **服务器状态维度（即 HTTP 语义）**：
    
    - GET 是“安全”的，因为它承诺**不修改服务器数据**。
        
    - POST 是“不安全”的，因为它通常用于提交数据，**可能修改服务器数据**。
        

#### 四、面试追问速答

- **Q: GET 和 POST 的本质区别是什么？**  
    **A:** 本质是**语义**不同：GET 用于获取资源（只读），POST 用于提交资源（写入）。底层实现上，两者都可以发数据，但协议约束和浏览器行为（如缓存、回退机制）完全不同。
    
- **Q: GET 请求的参数长度限制是由 HTTP 协议规定的吗？**  
    **A:** **不是**。HTTP 协议本身对 URL 长度没有限制，限制来自于**浏览器（如 IE 的 2083 字节）和服务器（如 Nginx 的 `client_header_buffer_size`）**。
    
- **Q: RESTful 风格中，这些方法如何对应 CRUD？**  
    **A:** GET → **R**ead（查询），POST → **C**reate（创建），PUT → **U**pdate（全量更新），DELETE → **D**elete（删除）。
    

#### 五、记忆口诀

> **GET 查数据，参数带 URL，安全幂等可缓存；**  
> **POST 提交改，数据藏 Body，不安全且不幂等。**  
> **数据敏感用 HTTPS，URL 长度非协议。**
