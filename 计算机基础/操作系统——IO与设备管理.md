### IO控制方式

#### 一、核心演进逻辑

**从CPU高度参与 → CPU几乎不参与**  
**目标：提高系统效率，减少CPU干预**

#### 二、四种方式对比（必背）

|方式|核心思想|CPU参与度|特点|
|---|---|---|---|
|**程序直接控制（轮询）**|CPU主动检查设备状态|**极高**|实现简单，但CPU忙等待，利用率低|
|**中断驱动**|设备完成后发中断通知CPU|**中等**|CPU不忙等，但中断处理有开销|
|**DMA（直接内存访问）**|DMA控制器接管数据传输|**低**|适合高速大批量传输，需额外硬件|
|**通道控制**|通道是专用I/O处理器|**极低**|CPU几乎完全解放，适合大型机|

#### 三、一句话核心

- **轮询**：CPU一直问“好了没？”
    
- **中断**：设备主动说“我好了！”
    
- **DMA**：硬件自己搬运数据，CPU只负责启动和收尾
    
- **通道**：I/O有自己的CPU，完全独立运行
    

#### 四、面试追问速答

- **Q: DMA传输过程会占用CPU吗？**  
    **A:** DMA传输时，DMA控制器占用总线，CPU可继续执行不访问总线的操作（如缓存命中）。但CPU仍需：**初始化DMA、启动传输、处理完成中断、处理错误**。
    
- **Q: 什么是零拷贝技术？与DMA有什么关系？**  
    **A:** 零拷贝避免数据在内存中多次复制。DMA是实现零拷贝的基础：传统方式需要2次DMA+1次CPU复制，零拷贝通过DMA让设备直接到用户缓冲区，只需1次DMA。
    
- **Q: 为什么需要中断？**  
    **A:** 避免CPU忙等待，让CPU在I/O期间执行其他任务，提高系统效率。

### IO模型有哪些？

#### 一、核心分类（一句话）

**I/O 模型决定了“数据准备好”和“数据拷贝”这两个阶段，进程分别要等多久。**

>IO控制方式与IO模型的区别：
> - **I/O控制方式**：关注的是 **“数据怎么传输”**（硬件层面，CPU与设备如何交互）。
> 快递怎么送？（是让用户自己跑腿去拿，还是快递员送货上门，还是用无人机配送？）
> - **I/O模型**：关注的是 **“应用程序怎么等待”**（软件层面，进程与内核如何交互）。
> 怎么知道快递到了？（是用户一直守在门口等，还是用户去门卫室问，还是快递到了按门铃通知用户？）

>- **数据准备好**：相当于**外卖已经做好了**，放在前台（内核缓冲区），等你来取。  
>- **数据拷贝**：相当于**你亲自去前台把外卖拿回桌子上**（从内核缓冲区拷贝到用户空间）。

#### 二、五种模型速览

|模型|数据准备好|数据拷贝|进程是否阻塞|
|---|---|---|---|
|**阻塞 I/O**|阻塞等待|进程参与，阻塞|全程阻塞|
|**非阻塞 I/O**|轮询检查，不阻塞（但CPU空转）|进程参与，阻塞|等待时不阻塞，拷贝时阻塞|
|**I/O 多路复用**|由 select/poll/epoll 代理等待|进程参与，阻塞|等待阶段代理阻塞，拷贝时进程阻塞|
|**信号驱动 I/O**|数据就绪后发信号通知|进程参与，阻塞|等待时不阻塞，拷贝时阻塞|
|**异步 I/O**|内核自动完成|内核负责完成，进程不参与|**完全不阻塞**|

>I/O 多路复用与信号驱动 I/O的区别：
>- **I/O 多路复用**：你（进程）主动去“问”内核：“有任何数据准备好了吗？”
>- **信号驱动 I/O**：内核主动“喊”你：“你关注的那个描述符有数据了！”

#### 三、核心概念澄清（面试必问）

> **同步 I/O vs 异步 I/O 的根本区别在于“数据拷贝阶段由谁完成”**

- **同步 I/O**（前四种）：数据拷贝阶段**需要进程主动参与**（进程阻塞，直到拷贝完成）。
    
- **异步 I/O**（只有第五种）：整个 I/O 过程（包括拷贝）由**内核自动完成**，完成后通知进程。**进程完全不参与拷贝**。

#### 四、面试追问速答

- **Q: 阻塞 I/O 和非阻塞 I/O 有什么区别？**  
    **A:** 阻塞 I/O 在数据就绪前进程挂起等待；非阻塞 I/O 立即返回（如 `EAGAIN`），进程需要轮询检查，但数据拷贝阶段仍需阻塞。
    
- **Q: I/O 多路复用（如 epoll）为什么比多线程阻塞 I/O 好？**  
    **A:** 单线程可同时监控多个连接，避免了创建大量线程的上下文切换开销。epoll 的事件驱动机制比 select/poll 更高效（O(1) vs O(n)）。
    
- **Q: 为什么说前四种是同步 I/O，只有异步 I/O 才是真正的异步？**  
    **A:** 因为前四种的**数据拷贝阶段都需要进程主动调用系统调用并等待完成**，而异步 I/O 的拷贝由内核完成，进程完全不参与等待。
    

#### 五、记忆口诀

> **阻塞全程等，非阻塞来回问，多路复用代等，信号驱动通知等，只有异步 I/O 不用等。**  
> **前四同步（拷贝需进程），最后异步（拷贝靠内核）。**

### poll为什么更加高效？

#### 一、epoll 高效的四点核心

> **事件驱动、内核回调、共享内存、边缘触发**

1. **事件驱动**：只返回**就绪**的 fd，无需遍历所有 fd。
>**fd 是 File Descriptor（文件描述符）的缩写**，在 Linux/Unix 系统中，一切皆文件。当你打开一个网络连接（socket）、一个文件、一个管道，或者创建一个新进程时，**内核会返回一个非负整数给用户程序，这个整数就是 fd**。
    
2. **内核回调**：通过回调机制通知就绪事件，**O(1) 时间复杂度**。
    
3. **共享内存**：epoll_ctl 和 epoll_wait 共享内核数据结构，避免数据拷贝。
    
4. **边缘触发（ET）**：只在状态变化时通知一次，减少重复通知，性能更高。
    

#### 二、三种 I/O 多路复用机制对比（必背）

|特性|select|poll|epoll|
|---|---|---|---|
|**时间复杂度**|O(n)|O(n)|**O(1)**|
|**fd 数量限制**|1024|无|无|
|**内存拷贝**|每次调用都拷贝|每次调用都拷贝|**共享内存，不拷贝**|
|**触发方式**|水平触发 (LT)|水平触发 (LT)|**LT + ET**|
|**编程复杂度**|简单|简单|中等|

> - **select/poll**：**“主动点名”** —— 每次都要先将fd集合拷贝到内核中，内核再从头到尾扫描所有的 fd，只为了找出哪些是就绪的。这个过程非常费时，特别是 fd 数量多时。
> >必须由内核确定 fd 是否就绪，是因为数据的内核缓冲区是用户程序无法直接访问的核心资源
> - **epoll**：**“等通知”** —— 内核维护一个“就绪列表”，当 fd 状态变化时，通过回调机制主动将就绪的 fd 加入到这个列表里。用户调用 epoll_wait 时，只需要把这个已经准备好的列表返回即可，**无需遍历所有 fd**。因此，epoll 的效率是 **O(1)** 的。

#### 三、水平触发 (LT) vs 边缘触发 (ET)

|特性|水平触发 (LT)|边缘触发 (ET)|
|---|---|---|
|**触发条件**|fd 就绪时持续通知|只有状态**变化**时通知一次|
|**数据处理**|可分批处理|**必须一次性读完所有数据**|
|**I/O 模式**|阻塞/非阻塞均可|**必须使用非阻塞 I/O**|
|**编程难度**|简单，不易丢事件|复杂，容易遗漏|
|**性能**|较低（可能有重复通知）|**更高**|

#### 四、面试追问速答

- **Q: epoll 的边缘触发模式为什么要用非阻塞 I/O？**  
    **A:** 边缘触发只通知一次，必须一次性读完所有数据。如果使用阻塞 I/O，读取时可能阻塞，导致其他 fd 饿死。非阻塞 I/O 确保读取到 `EAGAIN/EWOULDBLOCK` 时立即返回，避免进程阻塞。
    
- **Q: epoll 如何避免惊群效应？**  
    **A:** 惊群效应指多个进程等待同一个 fd，事件发生时全部被唤醒。解决方案：`EPOLLEXCLUSIVE` 标志（确保只有一个 epoll 实例被唤醒）、`SO_REUSEPORT`（内核级负载均衡）、应用层同步（互斥锁控制）。
    
- **Q: epoll 和 select 的 fd 限制分别是什么？**  
    **A:** select：`FD_SETSIZE` 限制（通常 1024），编译时确定。epoll：只与系统内存有关，通常支持数十万 fd。

> **水平触发常通知，边缘触发只一次，非阻塞 IO 要配合，高并发场景选 epoll。**

### 磁盘调度算法

#### 一、核心目标

> **优化寻道时间**，因为它是磁盘访问的主要瓶颈。

#### 二、七种算法核心对比（必背）

|算法|核心思想|平均寻道长度|饥饿问题|公平性|适用场景|
|---|---|---|---|---|---|
|**FCFS**|按请求到达顺序服务|最大|无|最高|负载轻、SSD|
|**SSTF**|选择离磁头最近的请求|较小|**有**（边缘请求可能饿死）|低|交互式系统|
|**SCAN**|磁头单向移动到尽头再反向（电梯）|中等|无|较高|负载较重的多用户系统|
|**C-SCAN**|单向移动，到尽头快速返回起点|中等|无|**更均匀**|实时系统、多媒体服务器|
|**LOOK**|SCAN改进，到最远请求就反向|较小|无|较高|平衡性能和公平性|
|**C-LOOK**|C-SCAN改进，到最远请求就返回|较小|无|**最均匀**|需要均匀响应时间的系统|

#### 三、关键算法速记

- **FCFS**：排队文化，简单公平但效率低
    
- **SSTF**：贪心算法，局部最优，有饥饿风险
    
- **SCAN**：电梯算法，一路到头再回来
    
- **C-SCAN**：循环扫描，只服务单向，回来不服务
    
- **LOOK**：SCAN改版，看到最远请求就回头
    
- **C-LOOK**：C-SCAN改版，看到最远请求就回头
    

#### 四、面试追问速答

- **Q: 为什么SSTF可能产生饥饿？如何解决？**  
    **A:** 新请求总是选择离当前磁头最近的，边缘柱面的请求可能永远没有机会成为“最近”。解决方案：**FSCAN**（将请求分为两个队列）、**时间片限制**（超时后优先服务）。
    
- **Q: 现代Linux实际使用什么调度算法？**  
    **A:** 早期使用**Linus电梯**（基于SCAN），后来使用**Deadline调度器**、**CFQ（完全公平队列）**、**NOOP**，现在常用**BFQ（预算公平队列）**。
    
- **Q: 固态硬盘（SSD）还需要磁盘调度吗？**  
    **A:** 需要，但侧重点不同。SSD无机械部件，寻道时间为0，调度算法重要性降低，但仍有优化空间（并发请求、垃圾回收）。

> **FCFS排队慢，SSTF贪心饿，SCAN电梯走，C-SCAN循环回，LOOK看到头就返，C-LOOK看到头就回。**  
> **寻道时间是瓶颈，算法优化找最短。**

### 设备管理的主要功能有哪些？

#### 一、核心功能

**分配、驱动、缓冲、中断、错误、虚拟化**

>1. 分配
**决定哪个进程可以使用哪个设备**。通过独占、共享或虚拟化策略，管理设备的使用权，确保设备被有序、安全地访问。
2. 驱动
**充当操作系统与硬件之间的“翻译官”**。将通用的软件指令转换为硬件能执行的特定电信号或控制命令，屏蔽硬件细节。
3. 缓冲
在内存中设立一个“数据中转站”。**暂存数据以协调CPU与设备之间巨大的速度差异**，避免CPU因等待慢速设备而浪费计算能力。
4. 中断
硬件主动“呼叫”CPU的机制。设备完成工作或有事件发生时，主动发信号通知CPU，**避免CPU进行低效的轮询等待，提高系统响应性**。
5. 错误
**对设备运行中出现的异常情况进行检测与处理**。根据错误类型（临时或永久）采取重试、标记坏块或上报失败等动作，保障系统稳定。
6. 虚拟化
**将单一物理设备抽象为多个逻辑设备，或把多个物理设备合并成一个逻辑设备**。通过模拟技术，提高设备利用率、灵活性和资源隔离能力。

#### 二、设备分配策略

|策略|含义|示例|
|---|---|---|
|**独占分配**|一次只供一个进程使用|打印机|
|**共享分配**|多个进程并发访问|磁盘|
|**虚拟分配**|通过SPOOLing技术将独占设备虚拟为共享设备|打印机虚拟化|

#### 三、驱动模型分类

|类型|访问方式|示例|
|---|---|---|
|**字符设备**|流式访问，无固定大小|键盘、鼠标、串口|
|**块设备**|块式访问，固定块大小，支持随机访问|磁盘、SSD、USB|
|**网络设备**|报文传输|网卡|

#### 四、缓冲管理

|类型|特点|
|---|---|
|**单缓冲**|一个缓冲区交替使用|
|**双缓冲**|两个缓冲区提高并行度|
|**循环缓冲**|多个缓冲区组成环形队列|
|**缓冲池**|系统级共享缓冲区|

#### 五、面试追问速答

- **Q: 字符设备和块设备的主要区别？**  
    **A:** 字符设备是**流式访问**，无固定大小，不支持随机访问；块设备是**块式访问**，固定块大小，支持随机访问，有缓冲区缓存。
    
- **Q: 什么是DMA？为什么重要？**  
    **A:** DMA（直接内存访问）允许设备直接与内存交换数据，无需CPU干预。优势：**减少CPU负担、提高系统并行性、提高大数据传输效率**。
    
- **Q: SPOOLing技术是什么？**  
    **A:** 将独占设备虚拟为共享设备的技术，提高设备利用率和灵活性。
    

#### 六、记忆口诀

> **设备管理六件事：分配、驱动、缓冲、中断、错误、虚拟化。**  
> **独占共享虚拟分，字符块设备网络。**  
> **单双循环缓冲池，DMA解放CPU。**
