### 处理机有哪两种状态？

#### 一、核心概念

> **核心态（Kernel Mode）**：操作系统内核运行状态，拥有**最高权限**。  
> **用户态（User Mode）**：用户程序运行状态，权限**受限**。

#### 二、核心对比（必背）

|对比维度|核心态|用户态|
|---|---|---|
|**权限级别**|最高（特权级0）|受限（特权级3）|
|**可执行指令**|**所有指令**（包括特权指令）|**仅非特权指令**|
|**可访问内存**|整个物理内存（内核+用户空间）|仅用户空间|
|**硬件操作**|可直接操作|需通过系统调用|
|**典型场景**|操作系统内核、中断处理、设备驱动|用户应用程序（浏览器、编辑器等）|

#### 三、状态切换

**用户态 → 核心态**（三种途径）：

1. **系统调用**：程序主动请求内核服务（如 `read`、`write`）
    
2. **中断**：外部设备请求服务（如时钟、键盘）
    
3. **异常**：程序错误或特殊条件（如除零、缺页）
    

**核心态 → 用户态**：

- 通过**中断返回指令**或**进程上下文切换**
    

#### 四、面试追问速答

- **Q: 用户态程序如何执行需要特权的操作？**  
    **A:** 通过**系统调用**接口请求内核代为执行。库函数（如 `read()`）会触发软中断或快速系统调用指令，导致CPU切换到核心态。
    >用户态可以进行的操作 = **不需要内核干预的计算和内存读写（纯 CPU 指令操作）**，完全在用户态完成，不切换模式。
- **Q: 为什么需要这两种状态的分离？**  
    **A:** 为了保证系统的**安全性和稳定性**。用户程序无法直接操作硬件或内核内存，防止恶意或错误程序破坏系统。
    
- **Q: 模式切换的开销包括哪些？**  
    **A:** **直接开销**：保存/恢复上下文、切换栈指针、更新CPU模式位、刷新[[操作系统——内存管理#三、实现方式|TLB]]。**间接开销**：TLB失效、缓存污染、分支预测失效。

#### 五、记忆口诀

> **核心态权限高，用户态受限跑。**  
> **系统调用切内核，中断异常也切换。**  
> **安全稳定靠分离，用户代码不能乱。**

#### 六、一句话总结

> **核心态与用户态的分离，是现代操作系统实现安全、稳定和多任务的基础。**

### 用户态和内核态的区别

#### 一、核心定义

- **用户态**：CPU运行**用户程序**的模式，权限受限，不能直接访问硬件。
    
- **内核态**：CPU运行**操作系统内核**的模式，拥有最高权限，可直接访问所有硬件资源。
    

#### 二、核心对比表（必背）

|对比维度|**用户态**|**内核态**|
|---|---|---|
|**权限级别**|低|高（最高特权）|
|**可执行指令**|仅非特权指令|**所有指令**（含特权指令）|
|**可访问内存**|仅用户空间|整个物理内存|
|**硬件操作**|需通过系统调用|可直接操作|
|**切换触发**|系统调用、中断、异常|中断返回、进程切换|

#### 三、两种状态切换（三种途径）

1. **系统调用**：程序主动请求内核服务（如 `read`、`write`）。
    
2. **中断**：外部设备请求服务（如时钟、键盘）。
    
3. **异常**：程序错误或特殊条件（如除零、缺页）。
    

> **一句话记住**：用户态切换至内核态，通过**系统调用、中断、异常**三种方式。

#### 四、面试追问速答

- **Q: 为什么需要这两种状态？**  
    **A:** 为了保证系统的**安全性和稳定性**，防止用户程序直接操作硬件或内核内存。
    
- **Q: 用户态程序如何执行特权操作？**  
    **A:** 通过**系统调用**请求内核代为执行。库函数（如 `read()`）会触发软中断，CPU切换到内核态执行服务代码。
    
- **Q: 状态切换时，硬件会做什么？**  
    **A:** 会保存/恢复上下文，切换栈指针，更新CPU模式位（如`PSW`寄存器中的模式位），可能刷新[[操作系统——内存管理#三、实现方式|TLB]]。
    

#### 五、记忆口诀

> **用户态跑应用，内核态管系统。**  
> **系统调用切内核，中断异常也切换。**

#### 六、一句话总结

> **用户态与内核态的分离，是现代操作系统实现安全、稳定和多任务的基础。**

### 如何将用户程序变为可执行程序？

#### 一、核心步骤（四步走）

> **预处理 → 编译 → 汇编 → 链接**

#### 二、各阶段核心任务

|阶段|核心任务|输入 → 输出|
|---|---|---|
|**预处理**|展开头文件、宏替换、条件编译|`.c`/`.cpp` → `.i`|
|**编译**|词法分析、语法分析、语义分析、代码优化、生成汇编|`.i` → `.s`|
|**汇编**|将汇编代码翻译为机器指令，生成目标文件|`.s` → `.o`/`.obj`|
|**链接**|符号解析、地址分配、重定位、库链接|`.o` + 库 → **可执行文件**|

#### 三、静态链接 vs 动态链接

|对比|静态链接|动态链接|
|---|---|---|
|**库代码位置**|复制到可执行文件中|可执行文件仅包含引用|
|**文件大小**|较大|较小|
|**运行时依赖**|不依赖外部库|需要动态链接器加载库|
|**库更新**|需重新链接|无需重新链接，库更新即生效|
|**内存占用**|每个进程独立占用|多个进程共享库内存|

>动态链接**不会冲突**，因为**代码段只读共享**，**数据段按进程隔离**。

#### 四、面试追问速答

- **Q: 编译和解释的区别？**  
    **A:** 编译**一次性**将源代码翻译成机器码，执行效率高；解释**逐行翻译执行**，便于调试，效率较低。即时编译（JIT）结合两者优点。
    
- **Q: 什么是重定位？**  
    **A:** 链接器将多个目标文件的相同段合并时，需要调整相对地址。重定位表记录所有需要修正的地址引用，分为**链接时重定位**和**加载时重定位**。
    >重定位就是：在合并多个目标文件时，把其中**那些“暂时留空的地址引用”填上真正的最终地址**。
- **Q: 如何减少编译时间？**  
    **A:** 使用**预编译头文件**、**增量编译**（make/ninja）、**分布式编译**（distcc/icecc）、**前向声明**替代包含头文件、**编译缓存**（ccache）。
    >前向声明就是**告诉编译器“有这个类名”**，让编译器**在编译头文件时先通过，从而避免包含整个头文件，达到减少编译时间和降低耦合的目的**。
    

#### 五、记忆口诀

> **预处编译再汇编，最后链接成可执行。**  
> **静态链接库复制，动态链接仅引用。**  
> **编译一次效率高，解释逐行调试好。**

### 软链接和硬链接的区别

#### 一、核心定义

- **硬链接**：原文件的**别名**，共享同一个 inode。
    >在 Linux 文件系统中，一个文件实际上由**两部分组成（文件名和标签inode）**，inode类似于一个**数字编号**，对应着文件数据在硬盘上的真实位置。
- **软链接**：独立的文件，存储**目标文件的路径**（类似快捷方式）。

 >**硬链接是“多胞胎”共享同一个身体（数据）**；**软链接是“导航”，指向目标**，目标没了就失灵。

#### 二、核心对比表（必背）

|对比维度|**硬链接**|**软链接**|
|---|---|---|
|**inode**|**共享**相同 inode|**独立** inode|
|**文件系统**|**不可跨**文件系统|**可跨**文件系统|
|**删除原文件**|硬链接**仍可访问**|软链接**失效**（悬空）|
|**链接目标**|**只能**链接文件|可链接**文件或目录**|
|**存储内容**|目录项直接引用 inode|存储目标**路径字符串**|
|**链接计数**|递增 inode 的链接计数|不计数|

>1. **目录也是一个文件**。普通文件存“数据”，目录文件存“文件名和 inode 的映射表”。
>2. **文件系统，你可以直接把它理解为“一个独立管理的存储空间”**，比如电脑上的一个分区、一个U盘、一张SD卡。

#### 三、关键考点速记

1. **硬链接不能跨文件系统**：因为 inode 号只在当前文件系统内唯一。
    
2. **硬链接不能链接目录**：防止形成目录环。
    
3. **软链接可以跨文件系统、可以链接目录**。
    
4. **删除原文件**：硬链接不受影响（链接计数减1），软链接变为**悬空链接**。

#### 四、面试追问速答

- **Q: 硬链接为什么不能跨文件系统？**  
    **A:** 因为硬链接直接引用 inode 号，而 inode 号只在同一个文件系统内唯一，不同文件系统的 inode 编号空间独立。
    
- **Q: 如何查看文件的硬链接数量？**  
    **A:** 使用 `ls -l`（第二列数字）或 `stat` 命令。
    
- **Q: 硬链接会不会造成循环引用？**  
    **A:** 对于文件，不会，因为所有硬链接地位平等。对于目录，系统禁止硬链接正是为了防止目录环。
    

#### 五、记忆口诀

> **硬链接共享 inode，软链接存路径名。**  
> **硬链接不能跨分区，软链接可以跨文件。**  
> **删除原文件：硬链接仍可用，软链接变悬空。**  
> **硬链接只能连文件，软链接连目录也行。**

### 作业调度、内存调度、进程调度的区别？

#### 一、核心对比（一句话）

**高级（作业）管“进场”，中级（内存）管“换位”，低级（进程）管“执行”。**

#### 二、核心对比表（必背）

|调度层次|别名|调度对象|核心行为|发生频率|解决核心问题|
|---|---|---|---|---|---|
|**高级调度**|作业调度 / 长程调度|外存中的**作业**|作业 → 内存（创建进程）|**低**|控制系统并发度（多少进程在内存）|
|**中级调度**|内存调度 / 交换调度|内存中**暂时不运行的进程**|内存 ↔ 外存（挂起/激活）|**中**|解决内存资源紧张（平衡负载）|
|**低级调度**|进程调度 / 短程调度|内存中就绪队列的**进程**|分配CPU|**高**|决定谁先获得CPU（快速响应）|

#### 三、工作层次（比喻）

- **高级调度**：像**酒店前台**——决定哪些客人（作业）可以入住（进入内存）。
    
- **中级调度**：像**客房调度员**——房间（内存）不够时，把暂时不用的客人请到休息室（外存），有空房再请回来。
    
- **低级调度**：像**餐厅服务员**——给已经入住的客人（就绪进程）安排座位（CPU）。

#### 四、面试追问速答

- **Q: 作业调度在现代操作系统中是否还存在？**  
    **A:** 存在，但形式变了。传统批处理系统中显著，现代操作系统以**隐式形式**存在（用户启动应用即创建作业），或转移到更高级别的调度器（如Kubernetes、Slurm）。
    >现代个人操作系统中，“所有人都可以入住”
- **Q: 这三种调度谁先执行？**  
    **A:** **高级（入场）→ 中级（搬动）→ 低级（执行）** 的流程顺序。
    

#### 五、记忆口诀

> **高级调度进场，中级调度换场，低级调度上场。**
