### DNS查询过程

#### 一、核心定义

> **DNS（域名系统）负责将人类可读的域名（如 `www.google.com`）转换为机器可读的 IP 地址。**

#### 二、DNS 查询八步流程（必背）

![[Pasted image 20260706204012.png]]

> **浏览器缓存 → 操作系统缓存 → hosts 文件 → 本地 DNS 服务器 → 根域名服务器 → 顶级域名服务器（TLD） → 权威域名服务器 → 返回 IP**

|步骤|查询目标|核心动作|结果|
|---|---|---|---|
|**1-3**|客户端本地|检查**浏览器缓存 → 系统缓存 → hosts 文件**|若命中，直接返回 IP|
|**4**|**本地 DNS 服务器**|客户端向本地 DNS 发起**递归查询**|若本地 DNS 缓存命中，直接返回|
|**5**|**根域名服务器**|本地 DNS 向根服务器发起**迭代查询**|根服务器返回**顶级域名服务器（如 `.com`）的地址**|
|**6**|**顶级域名服务器**|本地 DNS 向 TLD 服务器查询|TLD 返回**目标域名的权威 DNS 服务器地址**|
|**7**|**权威域名服务器**|本地 DNS 向权威 DNS 查询具体记录|权威 DNS 返回**目标域名对应的 IP 地址**|
|**8**|**返回与缓存**|本地 DNS 将 IP 返回客户端，并**根据 TTL 缓存**|客户端缓存 IP，下次请求直接使用|

#### 三、两大查询模式（高频考点）

|对比维度|**递归查询**|**迭代查询**|
|---|---|---|
|**发生阶段**|**客户端 → 本地 DNS 服务器**|**本地 DNS 服务器 → 根/TLD/权威服务器**|
|**特点**|客户端“甩手掌柜”，把查询任务完全交给本地 DNS 代理完成|本地 DNS “逐级问路”，每一级服务器只返回**下一级服务器的地址**，由本地 DNS 自己去下一级接着问|
|**结论**|递归找“代购”，迭代靠“导航”||

#### 四、核心优化机制

- **缓存优化**：各级 DNS 服务器都会缓存查询结果，减少全球查询次数。
    
- **TTL（Time To Live）**：控制**缓存有效期**（单位：秒）。TTL 到期后，缓存失效，需要重新查询。
    

#### 五、常见 DNS 记录类型（知识拓展）

|记录类型|含义|用途|
|---|---|---|
|**A 记录**|域名指向 **IPv4 地址**|最基本的记录，如 `www.example.com -> 192.0.2.1`|
|**AAAA 记录**|域名指向 **IPv6 地址**|处理新一代 IPv6 地址的解析|
|**CNAME 记录**|**别名记录**（Canonical Name）|将多个域名指向同一主域名，如 `www.programmercarl.com` 指向 `programmercarl.com`|
|**MX 记录**|**邮件交换记录**|指定域名的**邮件服务器**地址，用于发送和接收电子邮件|

#### 六、记忆口诀

> **本地缓存 hosts 查，无果找本地 DNS；**  
> **本地问根指 TLD，TLD 指权威，权威给 IP；**  
> **递归找代理，迭代逐级问；**  
> **TTL 控制缓存期，A/CNAME/MX 记心间。**

### 从输入URL到最终显示页面的过程

#### 一、核心八步流程

> **URL 解析 → DNS 查询 → TCP 连接 → 发送 HTTP 请求 → Tomcat/Servlet 处理 → 返回 HTTP 响应 → 浏览器渲染**

#### 二、分步详解（必背关键点）

|步骤|核心动作|关键细节与面试点|
|---|---|---|
|**1. URL 解析**|提取主机名、端口、路径|确定目标服务器和资源位置。|
|**2. DNS 查询**|将域名解析为 IP|**顺序查**：浏览器缓存 → OS 缓存 → `hosts` 文件 → 本地 DNS 服务器。本地 DNS 通过**递归查询**找根/TLD/权威服务器，拿到 IP 后返回并缓存。|
|**3. 建立连接**|TCP 三次握手 + TLS（HTTPS）握手|三次握手（SYN→SYN+ACK→ACK）。若 HTTPS，**TLS 握手协商会话密钥**。|
|**4. 发送请求**|组装 HTTP 请求报文|包含请求行、请求头、请求体（如 POST 数据）。|
|**5. Tomcat 处理**|匹配 Servlet，调用 `service()`|根据 `web.xml` 的 `url-pattern` 查 `<servlet-name>`。再根据 `<servlet-name>` 找 Servlet 实例（**若未加载，反射实例化并调用 `init()`**）。最后调用 `service()`。|
|**6. Servlet 处理**|封装 `req`/`resp`，调用 `doGet`/`doPost`|**⚠️ 注意安全**：Servlet 是**单例**的，但 `service()` 是**多线程**调用的，需注意成员变量的线程安全问题。|
|**7. 返回响应**|组装 HTTP 响应报文|状态行（如 200 OK）、响应头、响应体（HTML/JSON）。通过 TCP 连接发回浏览器。|
|**8. 浏览器渲染**|解析并绘制页面|构建 **DOM 树** → 构建 **CSSOM 树** → 合并为 **渲染树** → **布局（Layout）** → **绘制（Paint）**。|

#### 三、面试高频追问与加分细节

**追问 1：Tomcat 怎么通过 URL 找到 Servlet？**

> 它内部维护了**两个 HashMap**：一个 `Map<url-pattern, servlet-name>`，一个 `Map<servlet-name, Servlet实例>`。先通过 URL 拿到名称，再通过名称拿实例。若实例不存在，利用**反射**创建并执行 `init()`。

**追问 2：Tomcat 的 `DefaultServlet` 是干嘛的？**

> 当所有自定义的 `url-pattern` 都匹配失败时，Tomcat 会将请求转发给 `DefaultServlet`，由它负责处理**静态资源**（如 HTML、CSS、JS、图片等）。

**追问 3：浏览器渲染过程中，JS 脚本通常如何执行？**

> HTML 解析（构建 DOM 树）时，如果遇到 `<script>` 标签（默认没有 `defer` 或 `async`），会**暂停 DOM 树的构建**，立即去下载并执行 JS，执行完才继续构建 DOM 树（这就是为什么推荐 JS 放在 `<body>` 底部的原因）。

**追问 4：TCP 和 HTTPS 的握手顺序是怎样的？**

> **先 TCP 三次握手**，成功建立底层连接后，**再进行 TLS 四次握手**（协商加密套件、验证证书、交换密钥）。HTTP/3（QUIC）则将这两步合二为一。

#### 四、记忆口诀

> **解析域名查缓存，三次握手建连接；**  
> **请求先到 Tomcat，反射映射找 Servlet；**  
> **Service 调用出响应，返回浏览器建 DOM；**  
> **CSSOM 合并渲染树，排版绘制最终显示。**
